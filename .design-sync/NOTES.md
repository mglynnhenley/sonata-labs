# design-sync notes — @sonata/ui

- No dist: the package ships raw TS (`src/index.ts`); the bundle builds straight from it with `--entry ./packages/ui/src/index.ts --node-modules ./node_modules` (repo root — packages/ui has no local node_modules).
- Styling is Tailwind v4 compiled by the consuming app, so `.design-sync/build-css.mjs` compiles the real stylesheet (`packages/ui/.ds-css/sonata-ui.css`, gitignored) before the converter; `cfg.buildCmd` runs it. Utilities are scanned from `packages/ui/src` only — preview-only Tailwind classes may not exist in the compiled CSS, so previews use inline styles for layout glue.
- Fonts: Satoshi is vendored under `packages/ui/src/fonts/` and wired via `.design-sync/fonts.css` (`extraFonts`); Geist Mono comes from Google via a remote `@import` prepended by build-css ([FONT_REMOTE] is expected). `--font-sn-sans`/`--font-sn-mono` are normally set by next/font — build-css prepends a `:root` block defining them.
- `fonts.ts` imports `next/font/*` but is NOT reachable from `src/index.ts` (separate `./fonts` subpath) — the bundle never sees next/*.
- Grouping comes from `.design-sync/docs/*.md` stubs (frontmatter `category` + one usage line each); `docsDir` points there.
- Icons render 16px by default — their generated cards flag [RENDER_BLANK]/[RENDER_THIN] until authored with sizes/labels.

## Preview-capture gotchas (folded from wave learnings)
- Icon review sheets use a lowercase group prefix: `_screenshots/review/icons__<Name>.png`.
- One shared `Sizes` template covers all 23 icons; filled and stroked icons both inherit currentColor.
- Portals capture fine: the harness screenshots the full 900x700 viewport per story. ToastProvider's preview fires toasts with `duration: 0` plus a StrictMode double-fire guard.
- The capture viewport (900px) is BELOW the `lg` 1024 breakpoint: Sidebar renders in drawer mode and needs `open` plus a `transform: translateZ(0)` + `overflow: hidden` wrapper (contains the fixed drawer) and `style={{height:"100%"}}` to override `h-dvh`; SidebarTrigger is visible only under 1024. A future capture-viewport bump would blank both — revisit those two previews if the harness viewport changes.
- `cn` is a plain join (no tailwind-merge): inline `style` is the reliable override channel in previews.
- Config `overrides` edits mid-wave trip `[CONFIG_STALE]` on scoped preview-rebuilds — re-stamp with a full package-build before agents touch the overridden component.

## Re-sync risks (watch-list for the next run)
- The compiled stylesheet is regenerated by `cfg.buildCmd` from Tailwind sources — if `@sonata/ui` adds classes used only in previews (not in `packages/ui/src`), they silently miss the compiled CSS. The safelist in `.design-sync/build-css.mjs` covers the semantic colour families; extend it if conventions.md ever enumerates new class families.
- Geist Mono loads via a remote Google Fonts `@import` prepended by build-css ([FONT_REMOTE] expected). If Google changes the URL format, numerals fall back silently.
- Sidebar and SidebarTrigger previews depend on the capture viewport being <1024px (drawer mode). A harness viewport bump blanks both — regrade them after any capture-harness update.
- The Toast/ToastProvider previews depend on `duration: 0` keeping toasts mounted; a Toast API change to auto-dismiss would blank the cards.
- The first sync's Actions/Data/Display capitalized group dirs were uploaded once and reconciled away — group names now come lowercase from `.design-sync/docs/` frontmatter slugs. Keep frontmatter categories stable or old paths reappear as orphans needing reconciliation.
- Tailwind CLI (@tailwindcss/cli) and playwright live in `.ds-sync/node_modules` (gitignored) — a fresh clone must re-run the `.ds-sync` install line before `buildCmd` works.
